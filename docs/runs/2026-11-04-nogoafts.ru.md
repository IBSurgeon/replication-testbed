# Кластер без goafts на LXD-стенде ubuntu-1..3 (2026-11-04)

Итог: **путь клиента из руководства (гл. 1.3) пройден на Linux**: `fbagent
--cluster-init`, токены, `--cluster-join`, импорт подписанных выпусков,
участники и связи, узлы ставит агент из зеркала RCM. `test nogoafts` — 10 из
10, `test basic` — 8 из 8. Найдено и исправлено 2 ошибки fbagent и 3 ошибки
test bed.

План: hqcluster-node `docs/cluster-without-goafts-plan.ru.md`, §11.

## 3. Найдено и исправлено

| # | Где | Что | Исправление |
|---|---|---|---|
| 1 | fbagent | `--cluster-init` и `--cluster-join` от `firebird` не могли перезапустить службу агента («interactive authentication required»): агент работал без блока `cluster` | на Linux не от root — `sudo -n /bin/systemctl restart <unit>` (sudoers агента это разрешает); fbagent 75a452fb |
| 2 | fbagent | `sudo -u hqbirdrcm ./hqbirdrcm release import` из руководства — `Permission denied`: `/opt/hqbirdrcm` 0750 группы агента, а группа была только в юните (`SupplementaryGroups=`) | помощник root добавляет `hqbirdrcm` в группу агента (`usermod -a -G`); fbagent 75a452fb. Тест помощника искал `chown -R` и в тексте ошибки — теперь только в командах |
| 3 | test bed | `stage-rcm`: скопированный бинарник без права запуска, версия не читалась | `chmod 0755` перед `version` |
| 4 | test bed | `test nogoafts`, случай `status`: ключ `status` совпал с аргументом `Results.record` | ключ `report` |
| 5 | test bed | остался `replication.conf.lock` от root (0640, 23 октября): новый узел под `firebird` не мог писать conf, `scansync` → 500 | очистка (`fb_restore_pristine_conf`) удаляет этот файл |

Руководство (узел, гл. 1.3) и `rcm.md` (RCM): пользователь `hqbirdrcm` входит в
группу fbagent.

## 4. Страница «Настройки → Кластер»

Проверена в браузере через ssh-туннель к порту 7444. Показывает: документ
кластера (ревизия 3, `pki managed`, выпускающий CA), CA кластера и CA агентов,
4 агента (RCM-хост отмечен; отозванный агент проверки `reuse` помечен
`revoked`), 4 токена (used / revoked), участников `rcm`, `tb-master`,
`tb-replica1`, `tb-replica2`, связи мастер → реплики, статус участников
(`running`, ревизия 3), запросы сертификатов (`issued`). Ошибок в консоли нет.
