Подробно:

- **T1.** Установщики fbagent 2.57.0 ставят HQbird 2.5/3.0 **без плагина
  replconf и без `replconf.properties`**. Узел 2027.4.2 на таком хосте
  ничего не делает (пары T2 до обновления: `no replconf plugin`,
  `replconf.properties points to ""`). Новый узел сразу после установки
  агентом активировал свой файл сам (Р2, `not_set_up`): плагин
  `root:root 644` с закреплённым хешем, `replconf.properties` указывает на
  `/opt/firebird/replconf.hqcluster.hqbird`, `plugins/` и `bin/` остались
  `root:root 755`, корень `root:firebird 1775`. `GET /v1/replconf`: `active:
  true`, `plugin_version: 2.1.0`, дата 2027-03-31, `source: config`, без
  `activate_error`. Репликация: база на мастере, scansync, перезапуск
  Firebird мастера (2.5/3.0) или `publication/sync` (5.0), `reinit --mode
  standard`, вставка на мастере — строка на реплике через 15 с (3.0, 2.5) и
  45 с (5.0).
- **T2.** После перевода узла и RCM в `ops-test` агент обновил их до
  2027.4.2.3 (около 1 мин), и узлы на мастерах и репликах 3.0 и 2.5 сами
  активировали свой файл через fbagent. Репликация после обновления
  работает (15 с).
- **T3.** Дата кластера в goafts 2027-03-31 → 2027-06-30: `node.json` на 3.0
  через 7 с, на 2.5 через 4 с; файл узла получил дату, Firebird не
  перезапускался (тот же PID), узел перезапустился один раз. Дата убрана из
  кластера: `node.json` не тронут. Прошедшая дата (2026-09-01): не записана,
  в журнале агента одна строка `replconf_valid_till 2026-09-01 has already
  passed; node.json keeps its date`.
- **T5.** Реплика 2.5: узел остановлен, файл узла убран, корень
  `root:root 755`, узел запущен. fbagent 2.57.0 сам корень не открыл
  (11 мин): он открывает его при установке и обновлении узла, а не по
  расписанию. Корень открыт вручную, как это делает агент (`chgrp
  firebird`, `chmod g+w,+t`): узел создал файл через 54 с (проверка раз в
  минуту) и один раз повторил startup scansync.
- **T6.** Мастер 3.0, всё уже активно: dry run и повторная активация —
  `restart: false`, Firebird не перезапускался. `replconf.properties`
  направлен вручную на другой файл: активация по запросу прошла через
  fbagent (`check: true`, затем `check: false`, по строке в журнале агента),
  копия `replconf.properties.hqcluster-<время>`, один перезапуск Firebird,
  `bin/` и файл остались `root:root`.
- **T8.** Страница Databases (3.0, 5.0): вкладки Master-oriented,
  Replica-oriented, Combined (без «(test)»). На Combined блок на базу; вторая
  база мастера без реплики — строка «not paired» с Initialize.
- **Р2, окно мастера.** Мастер 3.0, плагин убран, `restart_window`
  `03:00-04:00`: узел не тронул Firebird, алерт `replconf_plugin_outdated`
  (warn) с причиной и временем открытия окна. Окно `always`: плагин
  поставлен через fbagent, Firebird перезапущен, `active: true`.
- **Падения Firebird 3.0 на репликах** при выключенных задачах трасс: нет
  (`firebird.log` на всех хостах 2.5/3.0 — 0 строк `terminated
  abnormally`).

Отдельные дроплеты (конфиги `r30`, `r25`: master + replica1, nyc3),
`install --source local` с теми же сборками (узел и RCM 2027.4.2.3, fbagent
2.57.0), `dbs prepare`, `loadgen deploy --from local`.

| Тест | 3.0.15 | 2.5.9 |
|---|---|---|
| `replconfdate` | все PASS | все PASS |
| `legacy` | 39 PASS после правки теста | 39 PASS после правки теста |
| `basic --minutes 5` | все PASS (строки совпали) | все PASS |

Тесты поправлены под решения этого выпуска (поведение узла верное):

- `replconfdate`, шаг `auto_activate`: мастер в окне рестарта (в test bed
  по умолчанию `always`) теперь переключается сам (Р2). Новая проверка
  «С-2 auto (Р2): the master in its restart window is switched» — PASS на
  обоих движках; прежние проверки мастера идут только при окне по времени.
- `legacy`, шаг `valid_date`: если дата узла — его дата по умолчанию
  (`valid_till_source: default`), `replconf_expiring` остаётся `info`
  (Р-С4), а не снимается. До правки — FAIL «valid date back» на обоих
  движках: дата вернулась верно (2026-11-01), но алерт `info` остался.

На реплике 3.0 test bed (задачи трасс fbagent включены, как ставит test
bed) — 17 падений `terminated abnormally` за прогон: известная ошибка
движка (заметки к выпуску, «Known issue»). Данные сошлись.

## 6. Замечания

- На реплике startup scansync при каждом старте узла после reinit пишет
  `scan would empty a previously-populated managed region` (базы реплики
  лежат в `<root>/<мастер>/`, шаблон не рекурсивный). Отказ безопасный,
  отдельная задача узла; к этому выпуску не относится.
- fbagent 2.57.0 открывает закрытый корень только при установке или
  обновлении узла (T5). Узел ждёт файл до 60 минут проверками раз в минуту.
