# 2026-11-20: перепривязка реплики после переключения (этап 0)

План: hqcluster-node `docs/switchover-keep-replicas-plan.ru.md`, вариант B.
Вопрос: может ли реплика C, которая была и осталась репликой, после
переключения A→B получать сегменты B **без reinit**.

## Стенд

- Два временных LXD-контейнера (Ubuntu 24.04), ванильный Firebird
  4.0.7.3271 и 5.0.4.1812 (установка `firebirdlinuxinstall/fb_vanilla-40.sh`,
  `fb_vanilla-50.sh`).
- На каждом сервере три базы: A мастер, B и C реплики (копия
  `nbackup -L` + `nbackup -F -SEQUENCE`). Сегменты из архива мастера
  копирует сам скрипт, node не участвует.
- Нагрузка: insert / update / delete, коммит раз в секунду,
  `journal_archive_timeout = 2`. Проверка: count, sum(id), sum(g),
  sum(hash(v)) таблицы на всех базах.

## Запуск

```sh
FB_PASSWORD=... ./2026-11-20-replica-rebind.sh s1   # или r1, r2, r3
```

Скрипт стирает `/data` и переписывает `/opt/firebird/replication.conf`:
только на чистом временном хосте.

## Сценарии и результат

| Сценарий | 4.0.7 | 5.0.4 |
|---|---|---|
| s1: A→B, C и A перепривязаны (`-replica none`, `-L`, `-F` без `-SEQUENCE`, `-replica read_only`, `source_guid` = G2, рестарт) | A = B = C (2 прогона) | A = B = C |
| r1: C без `nbackup -F`, только `source_guid` = G2 | не дошёл до переключения (Н-2) | C разошлась без ошибки |
| r2: сегмент 1 нового мастера не дошёл до C | C разошлась без ошибки | C разошлась без ошибки |
| r3: C отстала на последний сегмент A | сегмент без данных, проверки нет | C разошлась без ошибки |

- Без рестарта Firebird новый `source_guid` не действует: C пишет
  «Skipping file … due to GUID mismatch».
- `nbackup -L` работает на `read_only` реплике.
- `source_guid` в `replication.conf` — только в кавычках: без них
  `{…}` читается как начало секции («illegal line»).
- **Н-1.** База, открытая для перепривязки с секцией мастера в
  `replication.conf`, начинает новый сегмент: `REPLICATION_SEQUENCE` = 1.
  Как реплика она потом пропускает сегмент 1 нового мастера («is scanned,
  deleting», «continue from segment 2»). Секцию мастера убирать до шагов.
- **Н-2 (только 4.0).** Свежая реплика (`-SEQUENCE`, R = 4), получив
  сегменты 1…12 одной пачкой, после «continue from segment 5» пишет «No new
  segments found» и остаётся на копии; 3 прогона из 7.
- Имена сегментов: `<имя базы>.journal-<номер>`, без GUID. При одинаковом
  пути базы на хостах сегменты старого и нового мастера совпадают по имени.
